**`W45-GATEWAY-MEMO-KEY` (2026-09-26, base `2f9131a8`).** A soundness fix found by W45-AUDIT-CHECKPOINTS's independence audit ([report](../../reports/w45-gateway-memo-key/README.md)). The per-thread one-entry memo of `member_releasing_functions` (`legacy_member_release.rs`, W45-CALLEE-SUMMARY-CASCADE) served its answer, the set of unit functions the sub-custody guard must precede, whenever a 64-bit `DefaultHasher` digest of the token texts matched. It never compared the tokens, so a collision could hand one unit another's set, drop a guard and turn its refusal into an admission, with the colliding pairs depending on how `--jobs` scheduled units onto threads. The entry now keeps every token text and is served only when the digest and every text are equal; a collision is a miss. A test hook injects a colliding entry (miss, uncached answer), a control shows the hook reaches the memo, and a mutation harness kills 2 of 2 weakened checks. The feature `member-release-memo-off`, never enabled by any workspace member, compiles the memo out. A sweep of the gateway, audit, contract and core crates lists every memo, cache and interning table with its key and hit check: this was the only one served on a hash alone. Lean `QCore.MemoKey` (8 theorems): a memo that returns only on key equality is observationally the uncached function for every digest. Arbiter at `--jobs 8`: base, fix and cache-off runs, three of each, are byte-identical in all five artifacts, and verdict-bearing identity holds against the named baseline. Timing is within host noise: user CPU medians are 1,067 s for base, 1,063 s for fix and 969 s for off, with a ±7% scatter from other cards on the host. `W45-GATEWAY-MEMBER-RELEASE-MEMO-KEY` is discharged. It is registered only on W45-AUDIT-CHECKPOINTS's branch, so it is retired at integration.

(1) Clang instruments atomics and function entry/exit even in `no_sanitize("thread")` code, so the forcing header's exit barrier, which took and released its spinlock on every poll, gave ThreadSanitizer a new epoch and fresh trace events per iteration. After about 20,000 polls (a partner held about 5 ms) the waiting worker's own history was recycled, and TSan v3 dropped the planted race without output. Raising `history_size` to 7 only moved the cliff to about 10–20 ms. (2) The join-edge-removal stand-in slept 50 ms instead of waiting, so a worker still running after that touched a freed start record, and TSan reported a `heap-use-after-free` instead of a race, or nothing. The barrier now polls a change counter with relaxed loads and takes the lock only when a cohort table changed. The stand-in waits for the worker's completion flag, a relaxed atomic that carries no edge. A worker parked behind a gate only its waiting creator could open is not waited for. `Row::hold` holds one worker for a fixed time, and two new rows hold one for 100 ms: the pre-card barrier fails them 3/3 and the 50 ms stand-in 3/3. After the fix the file is red in 0 of 10, 40, 64, 96 and 128 runs at the same loads, and in 0/64 at 16 copies even with `history_size=0`. No assertion was weakened, no row was ignored, and `EXCLUSIVE` is unchanged. Test-harness only, with no analyser, verdict or Lean change. Retired `TSAN-JOIN-EDGE-ROW-LOAD-SENSITIVE`.
