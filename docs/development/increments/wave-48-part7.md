**`HOST-UNREAD-REQUEST-ACCEPTANCE-BY-SCHEDULING` (2026-10-13, base `e0b92ece6`, rebased onto `4807a71e8`; prediction `f6e5be232`).** The verifier host now decides a provider's successful exit from whether the provider consumed its whole request, not from write order ([report](../../reports/host-unread-request-acceptance/README.md); constraint [16](../../agents/providers.md#constraint-16) amended; Lean `QCore.RequestConsumption`, 8 theorems). Before, a provider that never read its request was refused (`Io(Broken pipe)`) when it exited before the host's write, and accepted when the frame fit the pipe and the write landed first. A census of every executable the host runs found no real provider that ignores its input: the eight Rust runtime providers and the w3 fixture read the whole frame, and the 13 non-reading shell fixtures were all already expected to fail. So the conservative default stands. The host now owns the request pipe and holds no read end while it writes. Once the frame is written, it opens a probe on the same pipe (Linux: `/proc/self/fd/<write end>`; elsewhere a read end kept from the spawn). Once the child has exited and its outputs are at end of file, it refuses with the new `ProcessOutcome::RequestUnconsumed` (`request-unconsumed`) when the frame was not wholly delivered, the pipe broke, or `FIONREAD` on the probe is non-zero. An unobservable probe refuses as `Io`, and an unsuccessful exit stays `Terminated`. A provider that reads exactly its frame and exits before the host closes its end is accepted. On a nine-case probe binary, under idle, 20 and 50 ms host stalls, and `LD_PRELOAD` delays of the first write, of the close, and of both with a stall, the base gave 317 deviating case-runs in 120 runs (the same silent provider accepted idle and refused with the write delayed).
