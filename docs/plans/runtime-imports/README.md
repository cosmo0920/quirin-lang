# Runtime source imports

Completed after the extension rename cards; [implementation and validation](../../reports/runtime-source-imports/README.md). The following requirements and agreed boundary record the accepted card scope. Runtime source spelling is **`#import`**, superseding the initially suggested `#include`. Contract inclusion keeps its own grammar and authority.

The implementation card must support relative `.qr` module paths spelled with or without the extension and `std.*` bundled-module names. Resolve relative paths from the importing file, retain source locations and explicit identities, and preserve file-local standard-module authorization. Define deterministic ordering, duplicate identity handling and cycle refusal. Missing, ambiguous, incompatible-mode or unsupported imports must fail closed. Do not infer an extension from unparsed content or silently load contract/ABI inputs into the runtime route.

Before implementation, inspect the existing runtime/library multi-file driver, parser and standard-module checker, commit a prediction and choose exact syntax with examples in the language specification. Compare direct multi-file compilation with imported equivalents, including emitted C, diagnostics and route selection. Add focused relative-path, explicit/implicit extension, standard-module, nested import, missing module, cycle, duplicate and wrong-mode cases. Include matching audited Lean for changed admission semantics and run the standing gate. This is a separate card after EXT-02/03; it does not delay or alter their filename-only parity claim. The user explicitly requires rewriting current `import std.*;` declarations to `#import std.*;`. The user explicitly requires updating or removing outdated historical examples as well: migrate archived source examples and runnable import snippets to `#import`, with original measurement provenance clearly distinguished. Legacy syntax support is a compatibility decision, not a reason to retain outdated examples.

## Agreed implementation boundary

Canonical forms are `#import std.fmt;`, `#import "./helper";` and `#import "../shared/helper.qr";`. Dotted names use the existing exact standard-module registry; `std.*` denotes that namespace style, not a wildcard. Quoted paths select runtime files, with precisely `.qr` appended when absent; there is no legacy-suffix, directory-module or environment search. Retain bare standard-import parsing as a compatibility route while migrating current and archived source usage; do not add bare relative-import syntax.

The ordinary compile APIs stay snapshot-only. Filesystem loading is explicit, and the CLI opts into it. Supplied snapshots take precedence over disk at the same lookup identity. Lookup/canonical identities must be separate from original diagnostic paths; ambiguous aliases refuse, and filesystem `..` must not be collapsed across symlinks before lookup. Traverse directives in source order, cache each loaded snapshot once, detect cycles, deduplicate repeated/diamond dependencies, and bound depth, modules and retained bytes. Imported dependencies may be unmarked or explicit library modules; contract and explicit executable dependencies refuse. Roots determine entry mode. Existing global declaration, duplicate-name, type/effect and profile rules remain authoritative; imports add no namespace/export or cross-profile-call feature.

Use a structural frontend import inspector that returns mode/header metadata and located runtime directives, not a publicly checkable program with unresolved imports. The ordinary parser/semantic entry points must reject unresolved runtime imports. After complete graph resolution, derive staging text by replacing only resolved runtime directives and mode headers with equal-length spaces while preserving newlines. Keep original `SourceFile` and diagnostic ranges unchanged. Run standard capability checks independently on every staged file before combining them; a helper's `std.io`, concurrency or unchecked-extern import must never authorize its caller. This follows the driver's existing mode-header staging and preserves task/epoch reparse checks.

Extend existing Q000 syntax/unresolved-frontend and Q014 resolution conditions deliberately; filename/mode mismatches retain Q403 and file-local capability refusals retain their existing diagnostics. The implementation report must distinguish the original snapshot from derived staging and document the filesystem boundary. Rust controls cover snapshot precedence, extension forms, cycles/aliases, diamonds, wrong modes, limits, capability isolation, original Unicode/CRLF locations and task/epoch replay. Register audited Lean for the admitted resolved bundle and per-file permission model, without claiming that abstract proofs establish filesystem or Rust-parser correspondence.
