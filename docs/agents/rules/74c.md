summary: A current-generation leak report is held and withdrawn only when the settled exit marks its identity by a refused release beside an `Unknown` leaf (a refused release is evidence of neither a discharge nor a leak); rule 10a's sparing frame reads `&NAME->F` as a use of `*NAME`, not of `NAME`'s slot, so a guarded `nonnull` release of a binding that survives is decided by the existing guard refinement.

74c. **A refused release is no leak; a member address does not take a
    name's slot.** Card NULLABLE-GUARDED-RELEASE
    (`crates/qcore-c-gateway/src/legacy_settled_leak.rs`, new; one hook in
    `report_leaks` and one after rule 42's settlement in the custody work
    list; one line in the frame computation of `legacy_c.rs`). It amends
    [rule 6](#constraint-6) and [rule 10a](#constraint-10a). (A) **Settled
    claims.** `report_leaks` runs on every iterate (rule 6), so an exit could
    claim a site before a refused effect's unresolved marker joined in; the
    claim was never withdrawn although the settled exit no longer made it
    (`rd_kafka_mock_handle_Metadata`: census `settled: false`, site
    `unresolved: true`). Every release `apply_resource_action` applies
    records the identities it marked when it refused
    (`AbstractState::refused_release_sites`, joined by union, renamed with
    loop generations). A current-generation report is held, as rule 42 holds
    an earlier generation's, and decided after the work list settles:
    withdrawn exactly when the exit node's settled incoming state marks the
    identity unresolved, a refused release is among the marks, **and** the
    function carries an `Unknown` leaf; published otherwise, and a key is
    published when any identity reporting it is not withdrawn. Only
    `Unsafe -> Unknown` moves follow. The refusal kinds that record are every
    refusing branch of that release: a nullable resource at a `nonnull`
    position, an unresolved or multi-target identity, an ambiguous cascade, a
    retained, holder, registry or taken object, a derived pointer. A marker
    from any other refusal (a refused test, a refused statement's hand-on, a
    refused re-acquisition, a refused escape) withdraws nothing here: rules
    12e, W44 and 42 keep those. What it costs: a genuine leak on a path that
    joins a refused release's path before the exit is withdrawn with it (the
    settled state cannot tell the two apart); the descriptor fixture
    `if (flag && k_close(fd) == 0)` is the pinned instance. (B) **The frame.** Rule
    10a's frame dropped every name a `&` is followed by; `&NAME->F` and
    `&(NAME)->F` take the address of a member of `*NAME` (C11 6.5.2.3,
    6.5.3.2), never of `NAME`'s slot, so the frame now reads the body through
    rule 12e's `member_addresses_read`, exactly the reading the tie names
    already have. A binding that survives a refused statement then reaches
    the guard, and the existing refinement (rules 14l, 10b) decides it: its
    non-null edge accepts the `nonnull` release, its null edge removes the
    site. For an array `NAME` the plain name's value (its address) cannot
    change either; its element places are not plain names and stay poisoned.
    **Do not** spare a name whose slot address is taken (`&NAME`, `&(NAME)`,
    `&NAME[i]`), a name written by the refused text, or a name the old
    exclusions drop; **do not** withdraw a report whose identity the settled
    exit does not mark, or beside no `Unknown` leaf; **do not** read the
    guard on an unknown binding (rule 10b stands). A refused statement
    keeps its own refusal, so it cannot make its function `Safe`; an
    *admitted* statement carrying the same frame (an indirect scalar store,
    card W43-INDIRECT-ACCESS-GENERAL's frame) no longer poisons a spared name, so a function whose
    only blocker was that poison can become `Safe` with its obligations
    discharged (`x_note(&r->count); *c = 0;` is the pinned instance). A spared
    binding can also expose a violation (rule 10a's recorded effect). Not covered, and
    recorded: a nullable binding made by a lazy constructor in a loop or by a
    poisoned binding joined at a loop head (seven of the eleven nullable-leaf
    rows of the held constructors card). `QCore.NullableGuardedRelease`
    (`a_refused_release_claims_nothing`, `the_marker_survives_the_join`,
    `another_refusal_withdraws_nothing`,
    `the_iterate_claim_was_unsupported`, `withdraw_vectors_hold`,
    `a_withdrawal_is_never_below_unknown`, `a_spared_name_keeps_its_value`,
    `the_frame_only_widens`, `a_slot_address_still_poisons`,
    `the_non_null_edge_denotes_the_site`, `the_null_edge_owes_nothing`,
    `a_reassignment_breaks_it`); [report](../reports/nullable-guarded-release/README.md).

Rule 74c is amended by [rule 84](#constraint-84) (card
SETTLED-LEAK-OTHER-REFUSAL-SCHEDULE): a held report whose settled exit marks
the identity by any refusal beside an `Unknown` leaf is no longer decided
here. Rule 84 publishes it exactly when a refusal-free witness carries it.
Rule 74c is amended by [rule 84](#constraint-84) (card
SETTLED-LEAK-MARK-WITHOUT-UNKNOWN-LEAF): the same holds beside a `Pending`
leaf with no `Unknown` leaf (a call held for a human act marks the identity);
only a mark beside no blocking leaf is still decided here.
