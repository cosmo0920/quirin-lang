---
rule: 81
topic: gateway
summary: Rule 10n (1)'s reading of `(&X)->f` as `X.f` holds in two more readers. In the lexical `may_bind` reader, a single `&` that opens a group `( & p SEL ) ->` (SEL member selections or balanced subscripts, no unary `&` before the group) takes no address of `p`. The elaborator's place reader reads an arrow over the address of a member or subscript place as that place's member. Each reads exactly the plain spelling `p SEL . f`.
---

81. **`(&X)->f` is `X.f` in the lexical `may_bind` reader and in the
    elaborator's place reader.** Card K6-DIRECT-POSITION-ACCESS, bundle K6 of
    CURRENT-ACCESS-ALIAS-CENSUS (`address_arrow_place.rs`: `ARM`,
    `dereferenced_address_group`; one delimited hook in
    `typed_field_access::is_written_at`'s address arm and one in
    `elaboration::path_place`'s `MemberExpr` arm, which calls rule 10n's
    `typed_position_shapes::arrow_through_address`). Macro expansion spells a
    member of an embedded record through the record's address:
    `TAILQ_FIRST(&p->q)` is `((&p->q)->tqh_first)`,
    `RD_KAFKAP_BYTES_LEN(&m->bytes)` reads `((&m->bytes)->len)`,
    `RD_KAFKAP_STR_LEN(&p->a[i].Host)` reads `((&p->a[i].Host)->len)`. The
    typed access-path reader already read these as `X.f` (rule 10n (1)), but
    the lexical `may_bind` reader read the `& p` as an address of `p`, so rule
    5b's pointer-return premise (rule 10k (2)) named `p`, and the elaborator's
    place reader refused a path through the `&`, so a rule 10z edge carrying
    the spelling was refused. In each case the plain spelling `p->q.f` was
    decided. C settles both readings: `E1->E2` is `(*(E1)).E2` (C11
    6.5.2.3p4), `*&E` is `E` (6.5.3.2p3), and a parenthesised expression is the
    expression it encloses (6.5.1p5). A postfix operator binds tighter than a
    unary one (6.5.2, 6.5.3), so the `&` of `& p -> q` takes the member place,
    never `p`, and the group's `->` dereferences that address at once, so it
    is no value of the program. Every condition and refusal is a formula of
    the C04.18.9 typed rendering over the K6 block (`k6_`-prefixed terms,
    sorts `k6_amp`, `k6_member`, `k6_place`), checked by the premise-formula
    validator `guarded_proposition` (`address_arrow_place::FORMULAS`,
    `crates/qcore-frontend/tests/rule81_formulas.rs`); prose glosses each.
    (1) **`may_bind`.** `k6_exempt_is_the_shape` and
    `k6_the_shape_is_exempt`:
    `forall (#a: k6_amp) { (#k6_exempt(#a) => ((((#k6_opens_group(#a) && #k6_name_arrow(#a)) && #k6_selection_chain(#a)) && #k6_group_arrow(#a)) && !#k6_outer_address(#a))) }`
    and its converse (the `&` directly follows `(`, the name is followed by
    `->`, the tokens up to the group's `)` are member selections and
    balanced subscripts, `->` follows the group, and reading back from the
    group through `(` meets no `&`).
    `k6_exempt_binds_as_the_plain_spelling`:
    `forall (#a: k6_amp) { (#k6_exempt(#a) => (!#k6_binds(#a) && !#k6_plain_binds(#a))) }`;
    `k6_at_least_the_plain_reader`:
    `forall (#a: k6_amp) { (#k6_plain_binds(#a) => #k6_binds(#a)) }`;
    `k6_only_removes_bindings`:
    `forall (#a: k6_amp) { (#k6_binds(#a) => #k6_old_binds(#a)) }`.
    Refusals: `k6_refuse_outer_address`
    `forall (#a: k6_amp) { (#k6_outer_address(#a) => #k6_binds(#a)) }`
    (`&((&p->q)->f)` is `&p->q.f`, which the plain arm binds),
    `k6_refuse_whole_address`
    `forall (#a: k6_amp) { (!#k6_name_arrow(#a) => #k6_binds(#a)) }`,
    `k6_refuse_operator_in_group`
    `forall (#a: k6_amp) { (!#k6_selection_chain(#a) => #k6_binds(#a)) }`,
    `k6_refuse_undereferenced_group`
    `forall (#a: k6_amp) { (!#k6_group_arrow(#a) => #k6_binds(#a)) }` and
    `k6_refuse_no_group`
    `forall (#a: k6_amp) { (!#k6_opens_group(#a) => #k6_binds(#a)) }`.
    (2) **Places.** `k6_place_is_the_plain_place`:
    `forall (#e: k6_member) { (#k6_over_member_address(#e) => (#k6_place(#e) == #k6_plain_place(#e) && #k6_root(#k6_place(#e)) == #k6_root(#k6_plain_place(#e)))) }`
    (the same spelling, root and indirection as `X.f`);
    `k6_place_only_adds`:
    `forall (#e: k6_member) { (!#k6_old_place(#e) == #k6_refused => #k6_place(#e) == #k6_old_place(#e)) }`;
    refusal `k6_refuse_whole_object_address`:
    `forall (#e: k6_member) { ((#k6_over_address(#e) && !#k6_over_member_address(#e)) => #k6_place(#e) == #k6_refused) }`
    (`(&s)->f`); a `.` over an address keeps the refusal too.
    Both readings only remove a binding or a refusal, and only where the
    plain spelling has none. **Do not** exempt an occurrence under an outer
    unary `&`, a group followed by anything but `->`, a group holding an
    operator other than a member selection or subscript (`(&p->q + 1)->f`),
    or `& p . q`. Do not widen the arm to `&p->f` outside such a group (the
    plain reader binds it on purpose, rule 75), or read `(&X)->f` in a
    reader that does not already read `X.f`. The rule changes no route
    order, premise or obligation: the read still carries every per-hop
    obligation of the plain spelling, so a read after a release is the same
    accusation and a rebound, consumed or addressed root keeps its refusal.
