---
rule: 84
topic: gateway
summary: A leak report whose settled exit marks the identity by any refusal (a refused release, hand-on, test, re-acquisition, escape or other marking refusal) beside an `Unknown` or `Pending` leaf, claimed on an iterate or not, is published when the custody work list replayed without every edge that marks the identity or carries a refusal still claims it at that exit and a producer-to-exit path keeps it live there; otherwise it is withdrawn, so the decision reads settled facts only.
---

84. **A withdrawn leak with a path avoiding every mark is published.** Card
    SETTLED-LEAK-JOINED-GENUINE-WITHDRAWN
    (`crates/qcore-c-gateway/src/legacy_joined_leak_witness.rs`, new; one
    call after rule 74c's settlement in `analyze_cfg_with_entry_collected`
    and one module line in `legacy_c.rs`). It amends
    [rule 74c](#constraint-74c) (A). Rule 74c (A) withdraws a report when
    the settled exit marks the identity by a refused release beside an
    `Unknown` leaf. The union join cannot tell the refused release's path
    from another path to the same exit, so a genuine leak on the other path
    was withdrawn with it. Whether an iterate claimed that leak at all
    depended on the schedule (rule 6): `if (flag && k_close(fd) == 0) {}` was
    claimed and withdrawn, and `if (flag) { k_close(fd); }` was never
    claimed. **The candidates** are, at every exit, the current-generation
    identities its settled incoming state marks unresolved with a refused
    release among the marks, when the function carries an `Unknown` leaf.
    These are exactly the reports (A) withdraws, held or not. **The
    witness.** The custody work list is replayed for the identity with the
    same transfers, edge refinements (rule 77's hook included), joins and
    schedule, except that an edge whose state marks the identity unresolved
    or is `unmodeled` (some instruction on the path was refused, or an edge
    taken was an undecided test or a retained infeasible loop exit) is not
    propagated. The restricted states are then joins over exactly the CFG
    paths on which nothing marked the identity and nothing was refused.
    Every refusing branch of a release marks its targets
    (`mark_unresolved_effect`), so none of those paths passes a refused
    release of the identity, and none passes a refused test's null edge, a
    refused hand-on, re-acquisition, escape or any refused statement. The
    refusal cut is required: without it a refused guard's null edge (rule
    10b) carries a site live that the test would have found NULL, the
    Metadata shape (A) was written to withdraw (`ampersand_run_parity`,
    `nullable_guarded_release` pin it). The leak `(exit line, acquisition
    line)` is published when both hold: the restricted exit output claims
    the identity by `report_leaks`' own conditions (`LIVE`, not exempt, not
    marked, no reference family) and is not `unmodeled`, and a breadth-first
    path from a producer of the identity to that exit keeps it `LIVE`,
    unmarked and unrefused on every restricted edge and node output it takes
    (the leak-witness census's search, over the restricted states).
    Otherwise the withdrawal stands, including for a leak whose only
    avoiding path passes an unrelated refused statement (the precision this
    keeps). **Premises:** (P1) the analyzer's
    path-feasibility reading, the one every published leak rests on: an edge
    no refinement proves infeasible is taken, and a `LIVE` bit at an exit is
    the may-evidence `report_leaks` publishes; (P2) every refused release
    marks the identities it could not discharge; (P3) the replay is the work
    list. Under `debug_assertions` the uncut replay is asserted equal to the
    settled states, so a hook added to the work list and not to the replay
    fails the gateway suite on any fixture with a candidate. Only
    `Unknown -> Unsafe` moves follow, plus extra `Leak` leaves in rows already
    `Unsafe`. Each published leak is provisional, beside the refused
    release's own refusal. Nothing becomes `Safe`. **Do not** publish a
    candidate whose only live paths pass a mark of it; **do not** treat a
    previous or older generation here (rule 42 keeps those); **do not**
    read a mark from any refusal other than a refused release as a
    candidate (rules 12e, W44 and 42 keep those, and 74c (A) does not
    withdraw them). Pinned instances (`tests/settled_leak_joined.rs`): the
    `condition_call_desugar` descriptor shape, a refused close on one arm, in
    a `while` loop, on two arms of three, beside an early return, and a
    nullable stream closed `nonnull` on one arm are `Unsafe`. The close on
    the only path, on both arms or in a `do`/`while` body, the other arm's
    refused hand-on, a discharging other arm and a returning other arm stay
    `Unknown`. `QCore.SettledLeakJoined`
    (`the_cut_join_is_the_avoiding_join`,
    `a_witness_avoids_every_refused_release`, `a_witness_passes_no_refusal`,
    `no_witness_through_a_refused_release`,
    `a_refused_only_leak_stays_withdrawn`, `publish_vectors_hold`,
    `an_unwithdrawn_report_is_untouched`, `a_publication_is_never_safe`,
    `the_pinned_instance`, `the_both_arms_control`);
    [report](../reports/settled-leak-joined-genuine-withdrawn/README.md).

Rule 84 is amended by card SETTLED-LEAK-OTHER-REFUSAL-SCHEDULE (same module;
the hook after rule 42's settlement now computes rule 84's candidates first,
and rule 74c's `Held::settle` skips them). **Every refusal kind.** A refused
hand-on, test, re-acquisition or escape marks its identity as a refused
release does, but rule 74c (A) withdrew only a refused release's mark and
rule 84 read only those. So a leak `report_leaks` claimed on an iterate
before another refusal's marker joined the exit was published, and the same
leak was not when the marker arrived first (rule 6's hazard;
`if (flag) { n = n + 1; u_keep(s); }` was `Unsafe` and
`if (flag) { u_keep(s); } else { n = n + 1; n = n + 2; }` `Unknown` at
`98c51878f`). **The candidates** are now, at every exit, the
current-generation identities that its settled incoming state, or the exit's
own output computed from it, marks unresolved by any refusal, when the
function carries an `Unknown` leaf (`decides`). Rule 74c's held reports for
those `(exit, identity)` pairs are left to rule 84, so whether an iterate
held one no longer matters. Each candidate is published exactly when the
restricted replay and the breadth-first witness above carry it, and is
otherwise withdrawn. The replay for one identity is computed once and shared
by its exits; the `debug_assertions` check runs once per analysis with a
candidate. Moves: `Unsafe -> Unknown` (a claim only an iterate made, with no
refusal-free path: the scram shape beside rule 42's refused re-acquisition,
`chained_assignment`; a leak past an undecided loop test,
`scalar_route_exit_edge`'s `z_unknown` row), and `Unknown -> Unsafe` (a
refusal-free arm in the marker-first order). Nothing becomes `Safe`: a
decided report sits beside an `Unknown` leaf. **Do not** decide a report
when the function has no `Unknown` leaf (amended below by
SETTLED-LEAK-MARK-WITHOUT-UNKNOWN-LEAF); **do not** treat an earlier generation here (rule 42's). Rule
W44's hand-on, rule 12e's settled null edge and rule 42's earlier-generation
accusations are kept wherever a refusal-free path carries the leak; a
refusal on every live path withdraws it. Pinned in
`tests/settled_leak_other_refusal.rs`: the hand-on, the escape and the
condition call, each on one arm in two schedules (both `Unsafe`), and each
on every path in two schedules (both `Unknown`). Kept pins:
`sup07_refused_test_accusation` (12e), `leak_pin_audit` (W44) and
`loop_reacquisition_leak` `refused-current-generation-leak` (42).
`QCore.SettledLeakJoined` (`a_witness_avoids_every_refusal_kind`,
`held_at_an_unmarked_exit`, `publication_is_order_independent`,
`the_old_decision_read_the_schedule`, `both_orders_publish_the_avoiding_arm`,
`a_refused_only_leak_stays_withdrawn_any_kind`,
`every_kind_on_both_arms_is_withdrawn`, `a_decided_report_is_never_safe`);

Rule 84 is amended by card SETTLED-LEAK-MARK-WITHOUT-UNKNOWN-LEAF
(`crates/qcore-c-gateway/src/legacy_mark_without_unknown.rs`, new: `blocking`,
`blocking_leaf` and the feature-gated `QCORE_MARK_CENSUS` census; in this
module `candidates` reads `blocking_leaf`, and the exit loop is
`marked_exits`). **A mark beside a `Pending` hold.** A call held for a human
act (rule 10i: a declaration awaiting review, a pin mismatch, a held callee
frame) refuses its statement with a `Pending` reason and hands its operands
on, so it marks them. In a function whose only blocking leaves were such
holds, rule 74c's held report was published exactly when an iterate had
claimed the identity: at `07833c86a` a held `k_close(h, 0)` on one arm and an
arm leaving `h` open was `Unsafe` when the open arm reached the exit first
and `Unknown` (no leak; rule 10i's standing analysis) when the held arm did.
**The side condition** is now a blocking leaf, an `Unknown` **or a
`Pending`** leaf (`blocking`), read on the diagnostics at the settle point;
the candidates, replay, witness and decision are unchanged. A withdrawal
removes only the `Leak`: the `Pending` leaf and its reason stay, so the row is
at least `Pending`, and rule 10i's standing analysis
(W45-REVIEW-HOLD-PREEMPTS-STATEMENT-REFUSAL) then records any reason the
function would carry with the held declarations in force (a leak there makes
it `Unknown`). No `Pending` reason is added or removed, and nothing becomes
`Safe`. **Do not** decide a mark beside no blocking leaf: withdrawing there
could leave a row with no non-`Safe` leaf, so rule 74c's held report keeps
deciding it (in the gateway suite such marks come from a modelled effect,
rule 43's `ElementsReleased` on an entry-custody site, and are never
claimable). Pinned in `tests/settled_leak_other_refusal/mark_without_unknown.rs`: the held
close on one arm in two schedules (both `Unsafe`, one leak, the hold kept),
on both arms (both `Pending`, the hold's reason only), and the open arm past
an unrelated held call (both `Unknown`, no leak, both holds kept).
`QCore.SettledLeakJoined` (`blocking`,

`a_pending_reason_is_preserved`,
`a_decision_beside_a_blocking_leaf_is_never_safe`,
