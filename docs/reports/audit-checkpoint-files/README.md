# Per-configuration audit checkpoints

Base: `2e44e963`. With `--checkpoint-dir`, each planned source translation unit and compile configuration now produces one complete ten-section `.qo` as its worker finishes. The full unit key is hashed into the filename, so two compile commands for one C file remain separate. Every file repeats the run plan and global inputs; the refutation-table identity stays intact. Schema 3 replaces inherited pretty-JSON payload strings with recursively typed binary values and closed numeric status/verdict/certificate codes; it refuses older schemas. Worker-side atomic write, file sync and rename happen before ordered publication; Unix also syncs the containing directory. Host-crash durability remains platform/filesystem-dependent. Workers print an immediate `checkpoint ready: PATH` line even if an earlier unit blocks ordered output; a linking line marks composition. The consumer then prints unit output in plan order and the composer rejects missing, duplicate, corrupt or mixed-run files before writing the report. A reordered selection re-seals reused units with the current library-header position. An interrupted run retains completed units for `--resume`; an unfinished `.qo.partial` is ignored.

The per-unit split is behavioral orchestration, not an analyzer change. `proof/QCore/Checkpoints.lean` now states the singleton-partition resume/compose theorem and `proof/AuditCheckpoints.lean` registers it. The proof assumes the Rust fingerprint captures every analysis input, as the existing checkpoint proof did. It does not prove SHA-256 collision resistance or filesystem crash consistency.

Memory bound: at most `--jobs` unit analyses and their individual checkpoint encodings are live; ordered consumption keeps only small completion records. A slow early unit cannot prevent later completed workers from sealing files, though the report waits for all planned units. Repeating the complete plan/global sections in each `.qo` uses more disk than the former per-library layout. No new opt-in flag is needed beyond `--checkpoint-dir`.
