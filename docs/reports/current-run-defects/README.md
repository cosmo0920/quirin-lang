## 2. Defect 2: `tinycthread.c`

**From the compile database.** The unit's command
(`lib/librdkafka-2.15.0/src`, `-DLIBRDKAFKA_STATICLIB`, librdkafka's
`generated/` include) reads `generated/config.h`, which defines
`WITH_C11THREADS 1` (line 52) at both `046accf6` and `66910c10`. The whole
body of `tinycthread.c` is inside `#if !WITH_C11THREADS` (line 28), so no
definition is compiled: `_cnd_timedwait_win32` is additionally under
`#if defined(_TTHREAD_WIN32_)` (line 389), but so are none of the other 29,
and every one of the 30 is inactive.

**What the route does with it.** The function inventory is the union of the
raw token scan of the unpreprocessed source and the definitions the
line-marked expansion attributes to the main source (E01-F1), so the 30 raw
names stay in the denominator (monotonicity), and the expansion attributes
none. The analysis enters the first inventory name, finds no definition and
returns `Unknown` with ``C function `_cnd_timedwait_win32` was not found``;
all 30 are `not_projected`. This is not inactive code read as live: no
inactive body is analysed. Keeping the unit `Unknown` rather than data-only
is a recorded decision (`docs/cycles/CYCLE_19_FLUENT_BIT_LIBRARIES_VALIDATION.md`:
"The unit remains fail-closed as `Unknown (0/30)` rather than being called
data-only or safe") and matches E01-TAIL-EXCUSE, which refuses `Safe` to any
unit with a compiled-out definition. It is not a contract or summary gap:
nothing is compiled to summarise. The defect is only the reason, which
reads as a missing Windows function.

**Fix.** `SourceDefinitionInventory::build_excluded_only` (complete, no
definition attributed by the expansion, a non-empty raw scan) and
`build_excluded_reason` (`crates/qcore-c-gateway/src/legacy_enumeration.rs`);
`projection::state_build_exclusion` (`crates/qcore-audit/src/projection.rs`,
both projection routes) replaces exactly the entry-not-found `Unknown` of
such a unit with the stated cause:

> no main-source definition remains after preprocessing under the unit's own
> compile command: its 30 raw-source definition(s) (first
> `_cnd_timedwait_win32`) lie in conditional groups the command does not
> select, so a definition to analyse was not found (build-excluded, kept in
> the denominator)

The status, the 30 `not_projected` rows, the empty function list and the
reason code (`incomplete-obligation-coverage`) are unchanged. Any other
result, including a unit with one live definition, is untouched.

**Fixtures.** `crates/qcore-c-gateway/tests/e01_denominator_coverage.rs`
(the `tinycthread` shape and three precision cases), and
`crates/qcore-audit/tests/build_excluded_unit.rs` (the published row on a
plain and a prepared unit, and a mixed unit's unchanged row). **Lean.**
`QCore.SourceEnumeration` (`buildExcludedOnly`; such an inventory's
definitions are exactly the raw scan, never empty, with no unanalyzable or
new row, and its verdict is neither `Safe` nor `Unsafe`), audited in
`proof/AuditSourceEnumeration.lean`.

**On the corpus** at the base the same unit has the same reason
(`eight-home`, 30 raw definitions); no system or slice unit has it.

## 3. Defect 3: `mk_vhost_set`

**The pin record.** `providers/qcore-provider-libevent/contracts.lock`
(format 3) holds `mk_vhost_set` as a **tip** entry: repository `monkey`
(`/home/cosmo/Documents/GitHub/monkey`), ref
`refs/heads/cosmo0920-missing-va_end-on-null`, reviewed at
`21a2c1908b42596317717436e5ce0420805bd523`, sites `include/monkey/mk_lib.h`
and `mk_server/mk_lib.c` (body `42ec7d2f…`). The run's contract sidecar
resolves the tip to that same commit (not moved since review) and holds the
entry out of force: `source-changed`, "differs in include/monkey/mk_lib.h,
lib/monkey/include/monkey/mk_lib.h, lib/monkey/mk_server/mk_lib.c,
mk_server/mk_lib.c", found body `16a603d8…`.

**The revisions.** The vendored `lib/monkey/mk_server/mk_lib.c` body of
`mk_vhost_set` is byte-identical in every prepared Fluent Bit tree on this
host, `66910c10` and `046accf6` included (nine revisions, each with its
Monkey copy; [scripts/mkset.py](scripts/mkset.py)), and every copy has the
defect the fix removes: the `!value` early return inside the `va_arg` loop
returns without `va_end` (`mk_lib.c:527-530`). The slice tree `34155955` is
not prepared on this host, so its copy was not read; the decision below
does not depend on it.

**Decision: not re-pinned.** Two reasons, either sufficient:

1. A re-pin at a Fluent Bit revision would record the defective body as a
   reviewed identity of a declaration written for the fixed one. The custody
   clauses happen to hold on both bodies (the defect is a `va_list`
   protocol fault, which rule 11w decides on the body), but the declaration's
   own text describes the fix, and a pin certifies that a person read the
   declaration against that body.
2. Tip mode is the user's decision (2026-10-02). Replacing it with reviewed
   identities is the user's call, and `TIP-VENDORED-PATH-PREFIX` already
   records the alternative (a declared path-prefix mapping), which would
   still not bring it into force here because the vendored body differs.

**Effect on the run.** None: no unit of the production compile database
calls `mk_vhost_set` (its callers are Monkey's own API tests and fuzzers and
`tests/runtime/in_kubernetes_events.c`, none compiled into the database),
and its own body is analysed as an undeclared definition either way. It
comes into force when Fluent Bit vendors the fixed Monkey and a pin or the
prefix mapping reads that copy.
