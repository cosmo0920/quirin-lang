# r0.3 R01/R02 concurrency lifetimes and R03 trust boundary

Baseline: main `5d0fb6d`. Scope: the explicit `model.concurrent14` event checker. The review's snapshot was not treated as execution evidence: four new regressions were first run against current production code and all failed (`baseline-regressions.log`, exit 101). They demonstrated accepted access after destruction, accepted custody transfer after destruction, destruction while another task retained positive permission, and post-join child execution.

## Implemented rules

Every numeric resource ID names one unique lifetime. Access (read/write/atomic/guarded) and custody transfer reject destroyed IDs. Successful destruction requires the live ID's custodian, no other nonterminal task's positive permission (including permissions allocated to future tasks), no other task's held guards, and vector-clock ordering after every recorded access to that resource. It removes custody and permanently marks the ID destroyed. Fixed permission records remain in the input; the dead-ID check revokes their ability to authorize access. New generations require distinct IDs, never reused addresses or descriptors.

Task execution authority is now distinct from retained vector-clock history. Join consumes the child handle and makes that task terminal; all subsequent child operations, including receiving custody and spawning descendants, reject. A child must close its guards and join its own children before collection. The parent inherits the child's clock. This reduced model treats explicit join as completion/collection; it has no separate result/error capsules and does not implicitly return permissions or custody. Permission accounting is not broadened by join.

Mutex authorization remains intentional. Each certificate identifies `ConcurrencyProfile::TrustedExplicitTrace` and names `InitialAuthorityAndUniqueLifetimeIds`, plus `GuardFootprintAuthority` and/or `SynchronizedCustodyEdges` when used. A held guard is still an admitted model premise about its supplied footprint. A true synchronized handoff remains an admitted synchronization edge. These fields do not establish those premises from source. No checked-invariant profile, native provenance proof, arbitrary-schedule guarantee, full source access-capability claim, or new CT mapping is delivered here. R03's stronger checked-invariant acceptance criteria remain future work; its explicit trusted-model boundary is implemented.

Because guard footprints are not independently represented, destruction conservatively requires every other task's currently held guard to be closed, even if an external invariant might describe it as unrelated. Previous guarded access must also happen before destruction through join or an admitted synchronization edge. Unmodeled loans/callbacks remain outside this reduced trace claim.

It covers all access kinds; guarded/spawned use after destruction; transfer after destruction; live/future permission holders; unordered prior reads; outstanding guards; release/acquire and join ordering; nested/repeated joins; every terminal-task event role; separate generation success and reused-ID mutation; and explicit trust-premise reporting. Existing same-mutex positive traces still pass.

All 523 workspace tests passed, as did formatting, Clippy with warnings denied, both reevaluation probes, the pinned submodule test and `lake build`. The worktree initialized Libevent at `d82464a277d0f42703702c4dfd9af6af38595a83`. `gate-results.json` records gate results. One intermediate linker attempt encountered transient SIGBUS; the unchanged code passed on retry and in the full workspace run.

Lean now includes executable lifetime transitions and trace replay, with proofs that destruction and terminal states persist across accepted steps/runs, dead resources reject accesses/transfers, joined tasks cannot act, and destruction requires quiescence and prior-access ordering. The existing abstract checker requires lifetime replay and its certificates name the trusted profile/premises. Prior-access ordering remains an input to the lifetime projection representing the Rust vector-clock check; this is not a Rust/Lean/C refinement theorem. Cycle 14 and whole-project audits contain no project axioms or placeholders.
