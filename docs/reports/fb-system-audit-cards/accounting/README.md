## Inventory and arithmetic

| State | What this path measures | Transitions |
|---|---|---|
| One `cio_chunk` | Physical chunk identity shared by output queue wrappers. It has one backing file and may be up/down. | Startup scans each stream's chunks; successful segregation locks and downs the chunk (`sb.c:399-482`). A mapped input chunk holds the same pointer (`sb.c:687-713`, `flb_input_chunk.c:1492-1497`). |
| `fs_backlog_chunks_size[o]` | Per-output sum of wrapper snapshots of `cio_chunk_get_real_size`, **not unique physical disk bytes**. | One wrapper and charge per matching output (`sb.c:317-349`, `262-289`); removal searches each output and subtracts its wrapper charge once (`214-259`). The add saturates on overflow and subtract resets to zero on underflow, so equality to the mathematical sum is conditional on no saturation/mismatch. |
| `fs_chunks_size[o]` | Per-output charge for mapped/live input chunks, using real file size or its delta, only when a configured limit is active and route bit is set. | Map adds the post-validation real size (`flb_input_chunk.c:1749-1779`, `3922-3967`); ordinary append adds `post_real - pre_real` (`3326-3337`, `3522-3534`); route release and destroy subtract once when counted (`815-845`, `2704-2741`). The helper likewise saturates/resets (`66-92`). |
| `total` in backlog collector | Sum of content bytes for chunks up in the backlog input stream at callback entry, then successful map's **pre-map content size** per chunk. It is neither file allocation nor RSS. | `sb.c:601-616,675-717`; `flb_input_chunk.c:2947-2954`; `lib/chunkio/src/cio_stream.c:257-275`; `lib/chunkio/src/cio_chunk.c:315-360`. ChunkIO's up-stream sum itself uses unchecked `size_t total += bytes`; mapped validation may truncate content (`flb_input_chunk.c:1520-1614`). |

For a routed output with an active `total_limit_size=L`, current mapped charge `F`, backlog-wrapper charge `B`, and projected incoming **increment** `P`, `flb_input_chunk_output_would_exceed_limit` accepts the arithmetic comparison precisely when `F <= L`, `B <= L-F`, and `P <= L-F-B` (`flb_input_chunk.c:1173-1200`). Equality is accepted; this is not a strict `<` check. The projection includes header/metadata and file allocation rounding, with checked overflow returning `SIZE_MAX` (`988-1097`). If the comparison fails, the caller attempts eviction (`1206-1255`); `place_new_chunk` rejects when eviction reports an unmet requirement (`1299-1316`, `2890-2909`). This is a **per-output accounting admission rule under ledger-correctness and post-write-size premises**, not a demonstrated physical disk, RSS, or cache bound. Fan-out charges the same physical chunk once in each routed output ledger. `sb_release_output_queue_space` removes wrappers from *all* routed queues and closes the underlying chunk once (`sb.c:551-577`), so one output's eviction has cross-output effects.

The backlog collector's `mem_limit` is a callback threshold, not a hard memory cap. It tests `total < limit` before an entire pass over output queues and adds `size` only after a successful map (`sb.c:604-616,715-722`). A single chunk can overshoot by its content size; a pass can map one per nonempty queue after the threshold has already been reached inside that pass. The mapped chunk is then downed at `sb.c:713`, so its content may cease to contribute to the next `flb_input_chunk_total_size` query. This needs a native trace before any numerical peak claim. `src/flb_storage.c:200-245` reports `mem_chunks_size` from the input's separate stream counter, so it must not be conflated with the output disk ledgers.

## Candidate questions and contrary guards

1. **Zero-progress callback cycle (highest priority).** If at least one queue head is nonempty and down and its `cio_chunk_up_force` repeatedly returns `CIO_ERROR`, `sb.c:649-651` continues without modifying `total`, that queue, or `empty_output_queue_count`. If every nonempty head does this, any empty queues increment the count but cannot reach the total queue count. The `while` condition at `611-612` remains true and the callback has no return/yield on that path. A persistent native open failure can supply `CIO_ERROR`: `cio_chunk_up_force` calls `cio_file_up_force` (`lib/chunkio/src/cio_chunk.c:590-604`), whose native-open error returns `CIO_ERROR` (`lib/chunkio/src/cio_file.c:816-850`); the chunk remains down because up requires an open descriptor **and** mapping (`cio_file.c:1377-1387`). `CIO_CORRUPTED` instead removes the shared wrapper(s) (`sb.c:635-647`), and a valid chunk maps/removes/increments total (`659-717`). This is a source-level possible cycle under a persistent open-failure premise, **not** a reproduced hang. The `CIO_RETRY` branch is written at `sb.c:649`, but this review found no executable `CIO_RETRY` return in `cio_file_up_force`'s pinned path; do not use it as reachability evidence. Test with a controlled ChunkIO native-open failure and an independent callback timeout; compare one valid-head control.
2. **Partial fan-out insertion failure.** `sb_append_chunk_to_segregated_backlogs` may append and charge an earlier output, then return `-3` when a later allocation fails (`sb.c:341-350`). The caller closes the physical chunk at `sb.c:435-475` without removing those earlier wrappers. `cio_chunk_close` frees that `cio_chunk` (`lib/chunkio/src/cio_chunk.c:111-138`), while the wrapper retains its pointer and charge until later cleanup or traversal. The append helper's `flb_calloc` failure branch exists (`sb.c:114-129`, `262-289`); whether a reproducible allocation failure can hit precisely the later insertion needs a native fault test. This overlaps custody and is a conditional stale-reference path, not a reproduced use-after-free.
3. **Size-basis and rollback questions.** Startup wrapper charge captures real size before map (`sb.c:317,346`); map can truncate content (`flb_input_chunk.c:1520-1614`) and charges the later real size at `1749-1779`; wrapper removal subtracts the *earlier* snapshot (`sb.c:228-238`). This is likely coherent only if the two ledgers are treated as separate states and remove/add ordering is atomic enough for the admission observer. `sb.c:319` checks `chunk_size < 0` after assigning an unsigned `size_t`, so that guard cannot catch a negative `ssize_t` real-size error converted to unsigned. The later behavior of such a chunk requires a targeted failing-size test. Saturation/reset avoids unsigned wrap but destroys exact-sum evidence; do not call it a checked-credit proof.
4. **Release-credit basis.** On failed admission the eviction helper receives `chunk_size=P` (`flb_input_chunk.c:1230-1245`), while the actual deficit is `P-(L-F-B)` when the ledgers are valid. This can evict more old routed bytes than the deficit. It may be an intentional policy, and the source does not yet show a user-facing guarantee of minimal eviction. Test a small deficit with one large queued chunk and compare the number of removed routes/files. `flb_input_chunk_release_space_compound` casts `size_t required_space` to `ssize_t` (`1115-1117`) and discards callee results (`1168-1170`); test values above `SSIZE_MAX` separately before any bound proof.
