# Native observation repair

The quiet-emission migration left native tests expecting implicit diagnostic
stdout. The masked-condition failure was an empty successful run passed to the
strict sequential observation parser. The repair explicitly installs typed
sinks in tests that compare native observations with their reference models.
Ordinary emitted programs remain quiet; source examples selecting
`log_level trace;` retain their published transcripts.

The shared test sink uses the maintained diagnostic adapter. The sequential
reader moves the final native outcome ahead of the recorded custody events to
match the historical observation format, preserving event order and strict
parsing. Task, extern, pipeline and reordering tests retain their native
comparisons. CT03 and CT17 execute both quiet and instrumented sanitizer runs;
the restored live fixture stdout constraints apply to the latter, while heap
and failure controls remain active. Example tests check source-I/O projections
with diagnostic logging omitted and run published traced examples verbatim
against their documented transcripts.

Two production repairs accompany the test migration:

- Quiet extern emission includes `<stddef.h>` for its use of `NULL`; native
  extern tests compile and execute both quiet and instrumented output.
- Mutex diagnostic metadata retains read-range endpoints and complete declared
  growth records. A mutex-specific test sink reconstructs the existing native
  observation without changing its reference model or weakening comparison.
  C still computes each read sum; protection growth remains declared
  bookkeeping, not a runtime mutex operation.

CLI native tests use the same explicit sink, and the unsafe-linkage example's
premise transcript now names its composed source-I/O profile. The compiler facade re-exports the
existing typed adapter so CLI tests retain their established dependency boundary.

Two nested `format!` calls in task emission are folded into `writeln!`, with
identical generated bytes. No checker rules, source effects, Lean definitions,
provider packages, schemas, contract corpus or frozen audit archives change.

## Validation

The initial discovery run found 36 failing tests, predominantly stale implicit
stdout expectations. Its log is preserved alongside the final run. The reported
`cycle19_current_command` missing-executable error was also checked separately:
the executable was present and the exact test passed. Overlapping Cargo runs
were stopped before final validation; no test or expectation was weakened for
that process-launch error.

The complete workspace run passed **3,579 tests**, with **8 ignored** and one
failure: the temporary CLI test dependency violated the existing layering rule.
That dependency was removed, and the adapter was re-exported through the
compiler facade. Final recompilation and reruns passed **31 bitwise-condition,
11 layering, 4 F02, and 13 CLI tests**. Thus all **3,580 distinct workspace tests**
are covered with no unresolved failures; this is a full run followed by the
final repair's targeted reruns, not a claim that the archived full run exited 0.

Formatting and Clippy (`--all-targets -- -D warnings`) pass, both reevaluation
probes exit 0, all **193 Python tests** pass, and all **95 Lean audits** pass.
Provider packages are unchanged; their 122-test checkpoint is carried, not
rerun. The frozen wave-23 corpus baseline is retained without a new corpus run.

`validation.json` distinguishes the workspace run from the final reruns. The
compressed logs preserve both the discovery failures and completed validation.
Native execution in this repair was on Linux x86_64; the shared sink is also
wired into the existing Windows-native test branches.
