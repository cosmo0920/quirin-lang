## Implemented boundary

`quirin check` and `emit` check suffix/mode agreement after parsing each input; mixed invocations keep their existing mode-composition rules. `.qr` includes library-mode source; `.qv` is contract mode and never a proof certificate. `.qrlib` identifies a native ABI manifest, whose `from` references stay exact. No missing legacy reference is resolved through an alternate suffix. A legacy/current pair with the same raw path stem is refused; `.qr` and `.qv` with one stem remain distinct runtime and contract inputs. Existing arbitrary virtual filenames remain supported.

The driver emits `warning[legacy-source-extension]` on stderr and exposes structured `CompiledModule.extension_warnings` plus `driver::input_extension_warnings` for callers, including refused inputs. These notices do not enter safety diagnostics. Contract and package readers emit the same named stderr warning without replacing their existing result schemas. A full parser refusal with no known mode is labelled unresolved. Parser intent is shared with the full grammar; the packaging probe classifies headers only and does not certify declarations.

Contract discovery, includes, provider load paths, inventory files and package integrity checks accept `.qv` alongside `.qcore`. Collision checks never choose by directory order. Native-reference and lock tests drive the new names; a stale reference still refuses. `Q403` extends the existing driver invocation condition to incompatible source names and aliases; `Q039` extends native-manifest loading to incompatible names and aliases. No code is allocated; the spec records both condition extensions. `QCore.SourceExtensions` models parsed-mode preservation and warning/outcome separation; this is an abstract companion, not extracted Rust or a proof of filesystem identity.
