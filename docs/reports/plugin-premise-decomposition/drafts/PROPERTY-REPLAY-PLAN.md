# Exact property-specific replay and publication plan

Resource replay continues through the existing resource loader and independently
held source/graph/manifest maps. Its audit publication may add original
rule-owned/literal/result-holder legacy records with `with_legacy` behavior;
those are retained in full, not rebound to a manifest by copying a presented
sidecar graph digest. A manifest binds the independently replayed declaration
graph, and checked publication separately verifies the actual augmented graph.

Bounds replay first uses `load_bounds_contract_sources`, preserving every
ordinary clause and canonical semantic digest, then freshly parses the same
exact supplied texts for `hypothesis::declaration` against original
`BoundsClause::Premise` records. The loader skips admitted graph metadata in
its interpreted clause list only after complete validation. Its written text
hash still covers all source clauses for deliberate official repinning.
`resolve_bounds` must perform this replay before reusing the exact generic
binding checks; it cannot pass resource replay, silently ignore a wrong marker,
or combine overlapping declaration names across property views.

Null graphs start from the exact existing row `null.premises` legacy records.
The actual `through` facts and `null.contract_dependencies` determine candidate
bounds declarations, using the existing member-fact premise relation, not a
name-only lexical scan. Match the original legacy text/origin and the bound
property source before importing a proposed refinement. Only its child atoms
and attachment are added; all old legacy atoms/records remain. Conflicting
atoms or attachments refuse the metadata publication; they cannot change the
null checker, fold, standing, runtime classification or a verdict. A source
manifest and full expected Context are independent explicit inputs.

A property-specific installed metadata record can retain the already-loaded
bounds source texts/digests for this replay; no process-global resource/bounds
graph map is merged. Existing public `BoundsContracts` and schema20 fields need
no expansion. No null parser admission is inferred from resource admission.

The model contract is a third explicit declaration-source replay view through
its already supported `module_premises`/hypothesis parser. It remains unpinned,
declared and unselected by C audit routes. Its graph/binding controls exercise
its actual written metadata without inventing a C source or published C row.

Both outer catalogs receive all inputs explicitly: independently held expected
canonical catalog bytes/digest, original actual outer source bytes, original
expected envelope identities reconstructed from official loader text hashes,
exact candidate inventory bytes/digest, loader-source identity records and
model/audit bytes. The actual outer loader reconstructs all definitions,
hosting loaders, runtime guards and envelope lines. Equality proves reference
integrity only, returning Open source binding. A separate card-owned Rust replay
can perform this bounded validation without a new source-language operator,
provider authority or hidden filesystem resolver.

Controls separately check wrong-property views, duplicate overlapping names,
missing legacy targets, changed bindings/graphs/source/model/audit/inventory,
canonical child order, caller-held expected Context across all nine fields,
exact direct/summary/member-fact consultation closure and unrelated rows.
Proxy creation with an ignored registration return cannot supply Supported
source evidence. Its absent check is neither a refutation of the old envelope
nor an upstream Unsafe: any hypothetical complete trace refutes only the exact
proposed candidate/registration prerequisite and dependent bridge/context.
