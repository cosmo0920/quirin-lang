## Explicit model environment

`QCore.PluginPremiseDecomposition.Environment` binds independently held full
Context, exact selected build/ABI and source revisions, plugin artifacts and
loader families (RK, Fluent Bit C, Fluent Bit Go), chosen artifact/path/handle
and symbol resolutions, descriptor/function ABI facts, static callback defaults,
actual call/callback/registration/interceptor events, code and opaque-context
liveness, conf/client phase and sharing state, object custody transitions,
core/internal memory writes, API calls/preconditions, cJSON hook/link events,
and close/unload events. The finite ordered trace must cover all interleaved
transitive loaded code within the declared scope/bounds; completeness and
source-to-model interpretation remain Open, not inferred from sampled traces.

Seven selected callback atoms name separate conditional Props:

1. `plugin_artifact_symbol_abi`: each reached loaded artifact has the expected
   selected bytes/build and every required symbol/descriptor has the exact
   recorded ABI. Loader availability or dlsym non-NULL does not establish it.
2. `plugin_callback_candidates`: each actual rk_conf invocation has an earlier
   successful public registration or stated static default for that member,
   and the invoked function meets that exact member's candidate contract.
3. `plugin_interceptor_registration`: each registration has result zero and
   the exact pinned list/union-arm/signature candidate; conf live, or client
   from on_new before initialization, never a share consumer.
4. `plugin_interceptor_custody`: every registered interceptor and transitive
   call borrows pointer/scalar resources, neither releases, retains, transfers
   nor changes global custody, and balances every local acquisition on return.
5. `plugin_code_context_lifetime`: at every invocation the called code and
   handed opaque context are live, including destroy and copied on_new paths.
6. `plugin_lifecycle_unload`: every invocation precedes the matching final
   close/unload; config destruction callbacks precede close; copies retain
   actual loader references. This is an explicit stronger prerequisite, not
   an equation with the old prose or a loader-refcount theorem.
7. `plugin_outer_bridge`: every actually loaded RK artifact satisfies the
   separately proposed RK envelope atoms; every actually loaded Fluent Bit
   artifact (C or Go) satisfies the separately proposed Fluent Bit atoms.
   The implication is guarded by actual loader family and exact independently
   bound envelope identity; one envelope never covers another's missing fact.

These conjunctions are proposed refinements only. They do not imply or follow
from the original English sentence. `compose_refinement` uses independently
held graph and all Context fields; legacy compose remains Open. Even complete
Supported refinement evidence supplies no new Safe, no Derived C fact, no
callback neutrality, and no provider authority. A detected refutation changes
only exact-context dependent evidence; it never automatically asserts Unsafe.

## Both outer envelopes: complete independent catalogs

The actual RK definition is rd_kafka_plugin_new / rk_plugin_library; Fluent
Bit's definition is flb_plugin_load / flb_external_plugin and its Go creator
inherits it. Preserve complete outer source bytes, original statement, every
envelope line/runtime guard, hosting-loader set, digest and selection semantics.
A separately supplied canonical catalog binds those independent exact identities,
the pinned outer-candidates bytes/digest, loader source hashes, model/audit
bytes and explicit environment. No implicit filesystem lookup or automatic
truth transport is allowed. Binding validation establishes reference integrity.

Both catalogs map every prose component, with nonempty explicit quantifiers:
public callback setter/candidate registration; public successful exact-arm
interceptor registration; transitive neutral custody and balanced acquisition;
callback code/context lifetime including destruction/copied on_new;
configuration/client initialization/share restrictions; unchanged cJSON global
hooks/no InitHooks; no direct child/prev/next writes and well-formed lists on
API entry; no direct librdkafka internal callback/op/broker/link/queue/list
writes; public-only librdkafka symbols and API preconditions; preexisting
allocator hooks satisfy their separately named premise. Fluent Bit additionally
maps no stores into any core-owned instance/config member, handed-object and
exported-API access only, and no pointer forging. The four stable descriptor
`.p` envelope lines are retained as specific consequences required of the
stronger no-core-store proposition, never inferred from successful load.

Loader availability, exact build/artifact/symbol/ABI, trace completeness and
unload ordering are additional guarded prerequisite obligations, explicitly
labeled as such rather than silently strengthening the old English premise.
Other named envelope premises (assignor, broker monitor, conf writer, share
batches, served queue, cJSON shape/hooks) remain separately registered; their
truth is not derived by this decomposition.
