# W44-LEAK-PIN-AUDIT: refused hand-on prediction, frozen before the rule is committed

Written on 2026-09-25, after the coordinator's two mid-card inputs and before
the refused hand-on rule is committed or measured by an AFTER arbiter. It
**adds to** [PREDICTION.md](PREDICTION.md), which stays frozen and predicts the
first design (cast return plus refused escape). This file is not edited after
the rule is committed; the report compares the outcome with it.

## The two inputs

1. **`W44-REFUSED-HANDOFF-LEAK-CLAIMS`** (from W44-COLLECTION-ALLOCATION): 107
   of that card's 125 new leak claims are an object handed to a refused
   statement. Classify every baseline leaf whose object is named in a refused
   statement on some path before the exit, as an argument, an operand or an
   address `&x`, and implement the sound rule: *a tracked identity named in a
   refused statement gets an unresolved effect on that path; no leak is claimed
   through an unresolved effect.* It never discharges an obligation and never
   makes anything `Safe`; only a mention the classifier can see counts. It is
   attributed as its own class, separable from the cast-return fix.
2. **`W44-CALL-ARGUMENT-EXPOSED-LEAKS`** (from W44-INDIRECT-CALL-ARGUMENT-ACCESS):
   its 11 exposed leaves come from three base semantics — an unsanctioned
   `*out = p` store, an object linked into a returned owner, and a release
   through an uncontracted helper. None of them is a baseline leaf here (each
   needs that card's admission to be tracked), so they are pinned by fixture
   ([`exposed_leak_mechanisms.rs`](../../../crates/qcore-c-gateway/tests/exposed_leak_mechanisms.rs)),
   not by corpus leaf.

## The rule the prediction assumes

`legacy_refused_operands.rs`, reader v3: at a node whose own transfer reported
`Unsupported`, every live identity the node's statement names — as a store's
value side or `return` operand (`Escape`), a call argument (`Call`), or any
other evaluated operand, including `&x` and an interior address `&p->f`
(`Operand`) — is marked with an unresolved effect after the transfer, with
`mark_unresolved_effect`'s cascade through `contained` and `field_links`. The
state join is the existing union of `unresolved_effect_sites`, and
`report_leaks` already skips a site in it. What is **not** a mention: a member
value read through the identity (`p->len`), an assignment's destination
(`p->f = …`, `*out = …`, `p[i] = …`), the base of a subscript, and the operand
of `sizeof`. A node refused as a controlling expression reads its line's
condition table; a node refused as a statement reads the statement table. Lean
`QCore.RefusedHandOnCustody` (the renamed `RefusedEscapeCustody`).

## Predicted outcome of the AFTER arbiter

* **leak 271 → 18**: exactly the 253 leaves marked `withdrawn`. No leaf that
  stays moves.
* **Functions 294 / 85 / 4,455 → 297 / 9 / 4,528**: 76 functions provisional
  Unsafe → Unknown (every leak of each is withdrawn and none carries another
  accusation; [prediction-handoff-movement.json](prediction-handoff-movement.json)),
  and the three cast-return `rdkafka_admin` accessors Unknown → Safe. **No
  other function moves to Safe**: the rule fires only at a node that reported
  `Unsupported`, so every function it touches keeps that refusal.
* **Units 3 / 43 / 135 / 4 → 3 / 8 / 170 / 4**: 35 units Unsafe → Unknown.
* **unsupported**: 45,848 − 4 (the cast-return deltas); the rule adds none.
  **unknown_alias**: 4,358 + 1 (cast return), plus possibly more where an
  unresolved site is later used; the direction is non-decreasing and every
  added one is attributed.
* **Violation candidates**: no `use_after_release`, `invalid_release` or
  `double_release` leaf is added or removed.
* **Fixtures**: all three exposed mechanisms are `Unknown` with no `leak`
  (with the rule off, each is `Unsafe` with a `leak`): mechanisms 1 and 2
  through a refused store whose value side hands the object on (`*out = p`;
  the link store `b->upper = upper`, which is itself refused), mechanism 3
  through a refused call argument.

### Risks recorded before measurement

* `report_leaks` runs on intermediate iterates (`C02-P-ALIAS-LEAK-ORDER`): a
  leak reported on an early iterate, before the unresolved effect reaches the
  exit, stays published. Any such leaf is a **missed** withdrawal and is listed
  by `attribute.py`; it is not repaired here.
* `withdrawn` is computed on the rule-off settled states; with the rule on, a
  withdrawal may change later states. A leaf that moves otherwise is
  attributed, not ruled out.
