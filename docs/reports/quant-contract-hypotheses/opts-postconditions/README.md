The formulas distinguish normal C failure returns from typed errors. Null name
implies result -1, unchanged field values/bytes, and no field commit event.
Success requires the three mandatory SDS contents and any requested optional
copies. Every surviving stored SDS is live and owned, even on failure. Failed
append preserves the previous fqname handle. Input consumption/retention,
record lifetime and resource-index representation preservation are separate
assertions. No assertion says every failure leaves partial ownership.

Exit states one release event per occupied field, retirement/ownership loss,
record survival, unchanged pointer/index bytes and unchanged stored pointer
values. Logical aliases refer to the retired allocation epoch; they do not
become physically cleared pointer objects. Repeating exit cannot reestablish
liveness. Separate map teardown eligibility and the absence of rollback are
comments about composition/classification, not unconditional exit guarantees.

Every field constant must bind to the exact five distinct C fields; the index
projection reads raw representation bytes, not an assumed initialized integer.
The before-state function view and existing environment predicates must bind
to the same actual fields and allocation epochs. All trace domains must cover
the entire selected call and its nested helpers/callbacks. Actual field/ABI,
range, environment, helper, epoch, source-to-model and Rust/Lean bindings remain
open. No formula's declaration establishes any of those inputs.

`QCore.CmetricsOptsConditions` audits representation preservation, selected
retirement, alias lifetime, failed append, index framing, retry liveness and
exact release-event selection under explicit inputs. It extends the prior
conditional CMetrics model; it does not prove arbitrary C allocator behavior.
