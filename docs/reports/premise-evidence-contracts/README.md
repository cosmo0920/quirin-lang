# Concrete premise evidence contracts

The production `cJSON_DetachItemViaPointer` contract now attaches nine formal
representation atoms to its existing `detach_list_representation` premise.
The exact old premise name, text, singleton and erasure remain separately
available. This is an independent proposed conjunction: neither its support nor
its refutation establishes or refutes the original English proposition.
Validation is in progress; no completed gate or fresh coverage claim is made yet.

The [preimplementation design](design.md) and [binding addendum](binding-addendum.md)
precede implementation. [Expected graph](expected-graph.json) is independently
held graph v2; [canonical binding manifest](binding-manifest.json), its
[readable derivative](binding-manifest-readable.json) and [content addresses](binding-address.json)
bind exact atom identities to formal proposition names, model/audit bytes,
quantifiers, prerequisites, conclusions and an explicit environment. All nine
source bindings remain **Open**. Reference-integrity replay supplies every
artifact explicitly; there is no implicit filesystem discovery or derived truth.

The environment names the current invocation actor, parent, finite child
sequence, owned/live predicates, child/next/prev maps, interference trace and
source/build/property scope. The nine propositions cover chain membership,
distinctness, empty equivalence, first/last equations, live link targets,
other-actor writer exclusion, parent exclusion and predecessor equations.
The existing cJSON model proves conditional live-link and distinct-index
implications and a writing-step counterexample. New audited attachment theorems
separate legacy truth from proposed composition and bind impact to exact
context plus actual declaration dependencies. Model proofs do not establish
that an arbitrary C heap, calling environment or trace satisfies those premises.

Graph v1 keeps its exact canonical bytes and digests. V2 adds a separate
refinement map and rejects unsupported versions; old readers reject v2. Schema
20.0 is a deliberate public Rust compatibility change and requires all five
provider packages rebuilt and verified. No predicate is registered, no operator
is added and no semantic consumer/classifier exception is introduced.

The declared manifest requirement travels beside the actual consulted graph.
`hypothesis_bindings::resolve` checks supplied expected graphs/manifests and
artifact bytes; `publish_checked_bindings` emits reference-integrity-only
publication. The report replay example accepts explicit sidecar, expected graph,
expected/presented manifest and artifact-index paths. The addressed manifest is
an explicit supplied input shipped with this report; general CLI/package
manifest routing is a follow-up interface concern, not hidden lookup behavior.

Compatibility acceptance compares six **fresh own** base/tip audits in the
[current merged eight-home context](baseline-and-context.json): every static
row/reason/standing, full null record, runtime record and actual closed-world
fact. Graph/source/pin/root/environment/configuration/time metadata differences
must each be attributed exactly. Unrelated v1 graphs stay byte-identical. The
impact artifact selects an independently held actual Context, enumerates direct
and summary users, and preserves unrelated/other-context records. Synthetic
`noWriter` refutation affects proposed composition only; it does not validate a
reachable C violation or mint Unsafe.

[Retained attempts](validation-attempts.json) include every failed gate/control.

semantics, path coverage and termination obligations; this card adds none.
