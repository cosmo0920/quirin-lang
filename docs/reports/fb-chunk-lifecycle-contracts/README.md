### Why most helpers in `flb_input_chunk.c` stay undeclared

Most of the uncontracted helpers in `flb_input_chunk.c` have custody-neutral
bodies. On custody alone they would read `resource_borrowed`, `resource_return_none`.
They stay undeclared because each reaches a log callback, and an earlier card
refused exactly that. `flb_input_chunk_output_size_subtract` and
`flb_input_chunk_update_output_instances` were refused an unconditional
neutral contract (W46-FLUENT-ACCOUNTING-LOG-CALLBACK-EFFECT): `flb_warn` can
invoke a configured log callback. A declaration with no counted-user clauses
is applied as user-neutral in every unit that does not define the body
(`legacy_counted_users::call_effect`: an empty clause set is `Neutral`), so a
borrowed-only declaration *is* that unconditional neutral contract. The same
reach holds for `input_chunk_output_size_add`, for the routing queries
through `flb_routes_mask_get_bit`'s out-of-range `flb_warn`, and for
`update_logs_tag_records_untracked` through `cmt_log_print`'s
`cmt->log_cb`. The ChunkIO-reaching wrappers (`get_event_type`,
`get_projected_write_size`, `set_up`, `write`, `get_input_chunk_record_count`)
reach `cio_log` through `mmap_file`, `cio_file_up` or `cio_file_write`, which
is W46-FLUENT-METADATA-CALLBACK-EFFECT's reason. Re-admitting any of them is
the refusal the common brief forbids, so they are class (b), and the two
follow-ups are amended to name them.

A checked specification (`requires resource_body_checked`) does not help
either. Every same-unit callee that appears as uncontracted has a body that
is not Safe (otherwise its validated W4 summary would be used), so a checked
specification would be withdrawn in exactly the unit where its callers are.

`flb_input_chunk_get_tag` is class (b) for a further reason: a
`resource_borrowed` out slot would hide an overwritten tracked identity in
the caller's `tag_buf`. And `resource_out_derived(tag_buf, ic, nonnull)`
cannot be checked by rule 13a, because the value arrives through
`input_chunk_metadata_view`'s out struct and is ended by closing the ChunkIO
chunk, not by releasing `ic`.

## The contract (class (a))

`flb_input_name` (`src/flb_input.c:1143-1150`) returns `ins->alias` or
`ins->name`, which are the instance's own strings, and does nothing else. It
is declared in `providers/quirin-provider-fluent-bit/contracts/fluent_bit/input_chunk_name.qv`
beside the chunk-name accessor:

```
extern fn flb_input_name(ins: ptr<mut, u8>) -> ptr<const, u8>
contract {
    requires resource_contract_v1;
    ensures normal resource_borrowed(ins);
    ensures normal resource_return_borrowed_from(ins, nullable);
};
```

`nullable` because the body does not establish that `name` is non-NULL. In a
unit that defines the body, rule 13a keeps the declaration only if every
return is NULL or a member read of `ins`. Elsewhere it is a premise read
from this body. Under C04.3.4 the name owns nothing: releasing it is
refused, never accused, and the borrow ends at `ins`'s release or at any call
naming `ins`.

**Fixture**:
`crates/qcore-c-gateway/tests/slot_move_interior_borrow/chunk_lifecycle_contracts.rs`,
a module of rule 13a's own target, so it adds no test binary. It loads the
production module.

| Shape | Without the card's text | With it |
|---|---|---|
| a caller unit reading the name (`strlen` on it) | Unknown, `call to uncontracted function` | Safe |
| the pinned body in the same unit, then the caller | (W4 summary) | Safe, no uncontracted leaf: the declaration stands |
| body returning a fresh `malloc` copy | - | caller not Safe: 13a withdraws the declaration, the body's own summary governs |
| body that frees `ins` | - | caller's own `free(ins)` not Safe: the declaration does not mask the release |
| `free` of the returned name | - | Unknown, no `InvalidRelease` accusation |
| a use after `free(ins)` | - | not Safe |
| `get_input_chunk_source_name` (`flb_input_chunk.c:525-538`) | `return` leaf + uncontracted call | two `return` leaves (the member-read actual) |

The loaded mode is pinned too: `Borrowed`, and `Derived { parameter: 0,
extent: Borrowed, nullable: true }`. `providers/contracts.py sync`
regenerated `contract-inventory.lock`: `input_chunk_name.qv` goes from 1 to 2
declarations and 4 to 7 clauses. `quirin-audit pin --source-root <046accf6>
--crate quirin-provider-fluent-bit --function flb_input_name` added its
`contracts.lock` entry: declaration and definition digests at 046accf6. The
lock-set window holds one set, so no other revision needed a pin. Both lock
diffs are in the semantic commit.

## Measurement

Base `56584db0b` and tip `b8470dedb`. Each was built from its own `git
archive` tree with its own release `quirin-audit` (sha256 `73b22fb0…d470f`
and `058d6be5…4f14b`), over the prepared Fluent Bit 046accf6 inputs, and each
route ran in an audit slot (`scripts/gate_slot.py`). The scripts are in
[scripts/](scripts/): `system.sh` is FB-RETRY-OR6-ELEMENT-IDENTITY's;
`opt-in-current.sh`, `totals.py`, `moved.py` and `changed_rows.py` are
FB-BACKLOG-ACCOUNTING's. The only change is the archived path of
`opt_in_providers.py`. The first base current attempt
(`private/fclc/run-base-current-attempt1`) exited 1 on the old path
("a contract load path is given but no provider is selected") and is
discarded. Logs are under this worktree's `private/fclc/`.

| Route | Base | Tip | Status moves |
|---|---|---|---|
| fluent-bit-system (448 rows, 15 units) | 116 / 0 / 328 / 4; units 13 Unknown, 2 Unsafe | 116 / 0 / 328 / 4; same units | none |
| opt-in `current --monkey-linked` (4,804 rows, 181 units) | 1,205 / 2 / 3,590 / 7; units 9 / 6 / 162 / 4 data-only | identical | none |

Rows are Safe / Pending / Unknown / provisional Unsafe. **The status
prediction holds: no row moves, so there is no Unknown -> Safe move to
justify.** Nothing here is an upstream defect claim.

**Leaves, against the prediction.** All 8 `call to uncontracted function
`flb_input_name`` leaves on the system route clear (3 on current), as
predicted. `get_input_chunk_source_name` trades its leaf for a
return-expression leaf at `:537`, exactly as the fixture predicted. Three
things were not predicted:

* The 5 `nested call `flb_input_name` inside a modeled call` leaves also
  clear (`input_chunk_append_raw` 3, `flb_storage_input_create` 2). The
  prediction said they would stay.
* Six rows gain 196 `use of X after its object moved or its parent changed
  (interior-borrow-ended)` leaves on the system route. Of these,
  `metrics_append_input` has 96, `handle_output_event` 58,
  `input_chunk_append_raw` 24, `update_logs_tag_records_metrics` 11,
  `record_retry_failure_metrics` 6 and `handle_dlq_if_available` 1. The
  current route has the `flb_input_chunk.c` share of these, 35 leaves. This
  is C04.3.4's rule 12y working as specified: a parent-borrowed name ends at
  any later call that names `ins` or an object outside the borrow's family.
  These bodies keep the name in a local across such calls, so each later use
  is refused. The refusal is fail-closed and never an accusation: every
  row was Unknown and stays Unknown. The prediction allowed a trade but
  did not count it.
* Statements that the uncontracted call used to refuse are now admitted, so
  `flb_storage_input_create` loses 8 indirect-access and 4 unresolved-identity
  leaves (`in`, `cio`). It now reaches `cio_stream_create` (2) and
  `cio_stream_get` (1) as uncontracted calls, plus one unresolved `cio`. Also,
  `flb_task_running_print` loses the indirect access at `flb_task.c:519`
  (`ins->p->name` beside `flb_input_name(ins)` in one print).

Per row and leaf, the lifecycle rows' changes are in [CENSUS.md](CENSUS.md)
under "What moved". The other units' changes are listed in this section.

The `parent-borrowed` mode was kept despite the leaf count. A
`resource_return_interior` result would not end at parent mutation, so it
would be quieter. But the strings are standalone heap blocks owned by the
instance, and C04.3.4 is the spec's mode for exactly that: releasing one is
refused, not accused as an invalid release. A quieter, less faithful
declaration is not the fail-closed choice.

Pinned routes (`quirin-audit measure --declared`) cannot run on this host:
there are no `build/cycle19` inputs or baselines. They were not run, and
nothing about them is claimed.
