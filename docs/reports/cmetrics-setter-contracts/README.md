All six public typed setter families and the public metric `set`/`unset` APIs in the inspected headers are accounted for. Increment/add/subtract/observe operations and internal `static` helpers are not setter API additions. Internal `map_metric_get_unlocked`, `map_metric_create` and `map_metric_destroy_unlocked` inform the existing public map models; they are not exported ABI contracts.

The new 15 declarations are **declared audit models**, outside interpreted resource/bounds/outer views. Their predicates are retained specification obligations; no interpreter is claimed to discharge their full conjunction. Existing interpreted scalar contracts describe only custody. They do not establish scalar value correctness, C numeric conversion validity, bounds, atomic layout/backend correctness, synchronization, progress or a coherent snapshot. In particular, double stores also convert to signed/unsigned integer mirrors; integer stores project into other representations under the selected C ABI. Start-timestamp writes store the value then the enabled flag, while unset stores zero to each. Individual atomic operations are not whole-record transactions. A future consumer must establish those stronger obligations separately. Existing source pins and interpreted permissions are preserved, and the consumer's canonical inventory digest is deliberately refreshed.

Every typed setter uses a writing lookup and keeps its representation, hash-zero accounting, nested-ownership and external-retirement obligations. Failure may retain map/index/storage changes. Counter additionally rejects a decrease when resets are disabled, without a following scalar set; its comparison and set are not one atomic operation. Histogram takes `bucket_count + 1` inputs and performs no input extent check; its integer defaults pass through double conversion and may lose precision. Counts must avoid loop/allocation overflow and undefined double-to-integer conversion. Summary accepts NULL quantile input, preserving the existing quantile values and set flag, although it can still allocate storage; existing target quantile extents/counts must be valid, and only admitted quantile slots are set. Exponential histogram copies each nonempty input, rejects a nonzero count with NULL input, frees temporary copies on preparation failure, swaps owned arrays under its metric lock and frees old arrays after unlock. Old raw aliases therefore need external lifetime coordination, and conflicting metric users (including writers and raw readers of plain metadata) must be excluded through return to establish the declared postconditions. Zero input counts install NULL arrays and release old storage. Inputs are borrowed, not retained or consumed.

Logging is also a premise: the inspected histogram lookup failure path supplies `histogram->map` to a `%s` format argument. This report establishes neither reachability of an invalid read nor an upstream defect. The histogram model explicitly requires valid logging contexts, formats and arguments under the selected backend; ordinary live-map ownership does not discharge that requirement. Trusted adoption must resolve it, rather than treating logging as a neutral total operation.

Rust controls parse all 15 actual canonical declarations, refuse resource/bounds adoption and exercise failed lookup, counter rejection, preparation failure, successful array replacement and nullable quantile flags. Eight added audited Lean theorems model preservation of lookup effects/parent ownership, preparation failure, old-array retirement/borrow invalidation and summary flags; nine shared lifecycle vectors bind the finite controls. Values are abstract tokens, not C floating-point semantics. Fresh/distinct replacement allocation, temporary cleanup, source extraction, synchronization and Rust/model correspondence remain premises (boundary 28), not a C refinement proof. No native verdict promotion or new planner ceiling is claimed. `CMT-MAP-OPTS-CONTRACT-ADOPTION` remains Open and now explicitly tracks setter conversion, extent, failure, replacement and alias obligations; the getter-chain and labeled hash-zero follow-ups remain Open.
