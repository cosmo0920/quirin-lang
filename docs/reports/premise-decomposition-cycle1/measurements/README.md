# Measurement scopes

`system/` and `slice/` retain the rejected production-companion attempt. Each
contains an immutable original-input base and a companion-input tip; those
selections have no users of the selected declaration. Their full record,
classifier and exact provenance comparisons are retained, but they do not
establish neutral publication for corpus callers.

`corpus/` contains only a compile-command correspondence receipt prepared
before the corpus comparison. There was no rejected companion-input corpus
tip: the immutable base audit continued while its orchestrator was briefly
paused, then the final original-input tip started after production restoration.

`final/` owns accepted original-input comparisons when complete. The fresh
immutable base runs are reused with their exact input/binary receipts, and
fresh tips use restored original production data. The system/slice final tips
run after the provider gate under the same advisory lock. The six-home linked
program premise is identical on both sides and is explicitly scoped in
`../linked-program-context.json`; it does not replace later seven-home safety
coverage. All metadata, null and runtime records remain archived. The actual
closed-world classifier is compared on every row, including unchanged Unknown.

Potential consultations of the report-owned nine-atom proposal are impact
candidates with an open attachment/source binding. They do not refute the
separate production legacy atom or change any production verdict.
