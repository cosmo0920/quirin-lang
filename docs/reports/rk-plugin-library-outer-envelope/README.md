# RK-PLUGIN-LIBRARY-OUTER-ENVELOPE

Base `fa04aab0f`, after NONNULL-MEMBER-UNIFIED-QUALIFIER. [Prediction](PREDICTION.md) was committed at `c0d919d25` before implementation. This card adds the second C04.20 outer contract, `rk_plugin_library`, on `rd_kafka_plugin_new`, at both audited Fluent Bit revisions. It keeps the static/runtime split of rule 31 and adds no promotion route.

## Contract boundary

`rd_kafka_plugin_new` opens the named library, resolves `conf_init`, passes its `rd_kafka_conf_t *` and returns `RD_KAFKA_RESP_ERR_NO_ERROR` after a successful initialization (or for an already registered duplicate). The loader's `#conf` binder and `when #result == 0` guard therefore name the loaded library's runtime reach. `RD_KAFKA_RESP_ERR_NO_ERROR = 0` in the audited `rdkafka.h`; the C04.20 guard parser accepts integer literals, so the design report's `#NO_ERROR` alias spelling is represented by that value. The `rk_plugin_library` contract condition requires every loaded library and the code it invokes to register rk_conf callbacks through public setters with the declared candidate contract, to avoid direct internal stores and non-public librdkafka calls, and to preserve cJSON allocator hooks. The envelope lists 34 rk_conf callback paths as `#registered` (17 member candidates and their 17 embedded `rk_conf` paths), the broker stable member, five rule-14t members, two op members, and four Fluent Bit instance descriptors as `#kept`, plus eight named premises. The interceptor `rd_list_t` members have no candidate contracts in the static callback registry, so this card does not put `#registered` lines on them; any row relying on their closed-world registration remains Unknown.

The first diagnostic run exposed a gateway reach defect: Clang can spell `rd_kafka_conf_t *` without `desugaredQualType`, and the record reader classified that unrecognized pointer as a scalar. The loader then reached zero records. An unclassified pointer now conservatively reaches every record; recognized primitive pointers remain empty. The reader removes recognized C qualifiers before checking primitive pointees, so `const volatile char * restrict` remains empty too. The focused Rust fixture tests these cases, and Lean names the two reach classes. The initial tip run is retained only as diagnostic evidence; the final comparison uses the repaired reader.

Source anchors at both pinned revisions: `lib/librdkafka-2.15.0/src/rdkafka_plugin.c:63-115` is the loader and success return; `lib/librdkafka-2.15.0/src/cJSON.h:150` exports `cJSON_InitHooks`; `providers/qcore-provider-librdkafka/contracts/librdkafka/client.qv:2305-2513` declares all 17 rk_conf setter registrations with `resource_callback_member_registered`. The Fluent Bit loader bodies and exported API reach are recorded in [stage 1](../outer-contract/README.md). The stronger restrictions are stated deployment conditions for external code. A reviewer must inspect the actually loaded libraries and their transitive calls; these source anchors establish the loader and candidate surface, not compliance by outside code.

The 164 librdkafka clauses (including the model-only destructor) and three Fluent Bit callback clauses that asserted `rk_no_plugin_library` are replaced by `rk_plugin_callback_closure`. It states the run's callback closure in the static scope and depends on the outer envelope when a library is loaded. It never asserts the absence of a loaded library. Declaration and clause counts are unchanged in those modules; the new outer module adds one declaration and its envelope clauses. All changed declarations need new resource/bounds pins at both revisions. The model-only `queue_destructor.qv` declaration retains its premise, with the new statement.

The final contract corpus pins `rd_kafka_plugin_new` at 57 clauses (`outer.qv` is the 136th module), `flb_plugin_load` at 57 clauses, and its unchanged `flb_plugin_proxy_create` citation at three. The replacement premise text now names both applicable outer envelopes, so resource and bounds declarations and three Fluent Bit logging declarations were re-pinned at both source revisions; the two outer definitions were re-pinned too. The pin script's targeted checks and `pin --verify-contracts` record each exit. A broad Fluent Bit resource `pin --check` from the first attempt exited 1 on unrelated pre-existing `flb_input_instance_destroy`, `flb_tail_config_destroy`, and `flb_tail_file_remove` source-changed entries; it is retained in `private/rk-outer/pins/` and is not counted as a passing gate.

Fluent Bit's outer binder reaches every record through `void *`, and a loaded Fluent Bit plugin can call librdkafka's exported API. The paired `flb_external_plugin` condition therefore states the same concrete restrictions on callback registrations, internal writes, cJSON hooks and published public-call conditions. Its defining loader has the same 34 rk_conf `#registered`, eight librdkafka `#kept` and eight premise lines, alongside the four original Fluent Bit descriptor lines. Each `Pending` is conditional on a human reviewing **both** loaded plugin classes against those statements; the static registry proves only that the member candidates exist. The contract does not assert that arbitrary deployed plugins already comply.
